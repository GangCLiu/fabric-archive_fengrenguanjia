# Honor 20 兼容性问题分析

## 现象与代码对应

用户反馈的三个问题（保存无响应、使用说明无法弹出、图片无法预览）在当前前端实现中都依赖 `web/app.js` 的脚本正常加载与执行：

- “使用说明”按钮事件在 `setupUsageModal()` 中绑定。若脚本初始化失败，点击不会触发弹窗。
- 图片放大预览依赖 `setupImageZoom()` 的全局点击代理。
- “保存”按钮依赖各表单的 `onsubmit` 处理函数。

## 高概率根因 1：旧 WebView 不支持现代语法，导致脚本整体失效

`web/app.js` 大量使用了以下语法：

- 可选链：`?.`
- 空值合并：`??`
- 可选 `catch` 绑定：`catch {}`

这些语法在较旧的 Android WebView/浏览器内核中会直接 **语法错误（Parse Error）**，导致整个 JS 文件不执行。

一旦出现这种情况，会同时解释你的 3 个现象：

1. 保存按钮无响应（`onsubmit` 没有被绑定）
2. 使用说明无响应（`onclick` 没有被绑定）
3. 图片无法点开预览（全局点击代理没有注册）

## 高概率根因 2：`crypto.randomUUID()` 在旧环境不可用

ID 生成函数当前为：

```js
function id(){return crypto.randomUUID();}
```

在旧 WebView（尤其是较老 Chromium）中，`crypto.randomUUID` 可能不存在。此时在新增记录点击“保存”会抛出运行时错误，表现为“点保存没反应”。

虽然这点无法单独解释“使用说明/图片预览”失效，但会叠加造成保存问题。

## 建议修复方向

1. **兼容性编译**：将 `web/app.js` 通过 Babel/esbuild 降级到 `es2018` 或更低目标，再发布到旧机型。
2. **替换现代语法**：手动将 `?.`/`??`/`catch {}` 改为兼容写法。
3. **ID 生成降级**：为 `crypto.randomUUID()` 增加 fallback（时间戳 + 随机数）。
4. **真机/模拟器验证**：重点在 Honor 20 的系统 WebView 版本上验证。

## 结论

根据代码特征，最符合你描述的主因是：**旧手机 WebView 与当前 `web/app.js` 的语法/API 不兼容，导致关键交互逻辑未正确执行**。
